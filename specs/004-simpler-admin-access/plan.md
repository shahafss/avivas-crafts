# Implementation Plan: Simpler Admin Access

**Branch**: `004-simpler-admin-access` | **Date**: 2026-11-11 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/004-simpler-admin-access/spec.md`

## Summary

Admin sign-in becomes one Google step for users whose new `role` is `admin`. The passkey step,
setup links, recovery codes, approval, lockout and the 5-minute re-check before export/anonymise
are deleted, with their screens, routes, jobs, alert kinds, interface text, dependencies, env vars,
tests and stored data. One command, `pnpm admin:role`, replaces `admin:add` / `admin:reset`. One
migration adds the role, drops the passkey/recovery/setup tables and columns, and ends all
sessions. Docs follow. Decisions: [research.md](research.md).

## Technical Context

**Language/Version**: TypeScript 5 (strict), Node 24

**Primary Dependencies**: Next.js 16.4.5 (App Router, Server Actions, proxy), Drizzle ORM,
`openid-client` (Google OIDC), next-intl. Removed: `@simplewebauthn/browser`,
`@simplewebauthn/server`.

**Storage**: PostgreSQL (Drizzle migrations); PGlite in integration tests; `test:pg` on real
PostgreSQL.

**Testing**: Vitest (unit + integration), Playwright (mock OIDC on 4011, axe), `pnpm verify`.

**Target Platform**: Render (Frankfurt) web service; phones first.

**Project Type**: single Next.js web application.

**Performance Goals**: no new runtime cost; admin bundles shrink (WebAuthn browser code gone).

**Constraints**: existing bundle budgets; `docs/design/storefront.md` edited by hand only (never
through prettier); spec 001 and 003 folders are frozen/historical and not edited.

**Scale/Scope**: two admins. Roughly 25 source files deleted, ~20 edited, ~15 tests deleted or
rewritten, 1 migration, 1 new script, ~13 docs updated.

## Design

### Data (see [data-model.md](data-model.md))

Migration `0003_*` generated by `pnpm db:generate` (in two passes if drizzle-kit asks "created or
renamed?": drops first, then the `role` column and `user_role` enum, merged into one `0003` with
its snapshot), then hand-edited so its
first statements are `DELETE FROM admin_session; DELETE FROM oauth_flow;` and, after adding
`role`, `UPDATE admin_user SET role = 'admin';`. The migration test copies migrations 0000–0002 and
a trimmed `_journal.json` into a temporary folder, migrates PGlite with it, inserts pre-004 rows
with raw SQL, then applies the full folder. Test the migration against a database holding
passkeys, recovery codes, setup tokens and sessions (integration `schema`/`migrate` tests and
`test:pg`).

### Sign-in (see [contracts/auth.md](contracts/auth.md))

- `src/server/auth/google.ts`: one purpose; `completeGoogleFlow()` adds the role check and creates
  the session directly; `REDIRECT_PATHS` and setup lookup go; returns `redirectTo =
  safeAdminNext(flow.nextPath) ?? '/admin'`.
- `src/server/auth/session.ts`: no stages; `createSession(adminId, {now, userAgent, tx})`;
  `getSession()` adds the role check (R3); delete `endPendingSession`, `rotateSession`,
  `markReauthenticated`, `PENDING_IDLE_MS`. Keep `listSessions`/`signOutEverywhere` only if still
  used (sign-out "all"); otherwise delete.
- `src/server/auth/require-admin.ts`: `requireAdmin`, `requireAdminApi` only.
- `src/server/auth/throttle.ts`: only `googleStartAllowed` remains (consider moving it into
  `google.ts` and deleting the file).
- Sign-in page: drop the `blocked` error code.
- Sign-out route: drop the pending branch; log `session.signed_out` for a single-session sign-out
  (FR-006).
- `src/server/security/notify.ts`: send alerts only to users with role `admin`.
- `src/server/auth/api.ts`: delete the WebAuthn request schemas.
- `scripts/measure-app-memory.ts`: insert its admin with `role = 'admin'` and no `stage`; drop
  the WebAuthn env vars.
- `src/proxy.ts` / admin bounce: drop references to removed paths if any.

### Customer tools

`customers/actions.ts`: `requireAdmin()` for export and anonymise; `CustomerSearch.tsx` without
`useReauthGate`; delete `ReauthGate.tsx`; remove `admin.reauth_required` handling and text.

### Command

`scripts/admin-role.ts` + `package.json` `admin:role` (see
[contracts/admin-role-command.md](contracts/admin-role-command.md)); delete `admin-add.ts`,
`admin-reset.ts` and their scripts; `scripts/dev.ts` uses `admin:role`.

### Removals

As listed in [research.md › R5](research.md#r5-what-is-deleted): modules, routes, pages,
components, the minute job, alert kinds, Google purposes, deps, env vars (`src/server/env.ts`,
`.env.example`, `.github/workflows/ci.yml`, `playwright.config.ts`), message keys in
`he.json`/`en.json`, test fixtures. `tests/helpers/admin-files.ts` lists of admin/API files are
updated so the guard tests still cover every remaining admin route.

### Docs (FR-014)

- `docs/design/storefront.md` (by hand): sign-in screens section (only the Google card and its
  errors), §12.7 export/anonymise (no re-check, line ~1224), state table row (~940), any passkey or
  recovery screen sections removed.
- `docs/privacy/*.{he,en}.md` (10 files): access authorisations (role command, Google 2-step
  verification), security procedure, incident response (sign everyone out = delete sessions; set
  role `user`), database definition (tables/columns removed), annual review checklist.
- Consent registry descriptions of `__Host-ac_admin` / `__Host-ac_oauth` and their message text:
  no passkey wording.
- `PRODUCT.md` › Admin sign-in (Google account with role `admin`; no passkey).
- `.env.example` comment for admin sign-in; `docs/roadmap.md` 004 status at the end.
- `CLAUDE.md` mentions nothing passkey-specific (check only).

### Tests (constitution VI; test-first where behaviour changes)

- Rewrite first, then code: `auth-google.test.ts` (role `admin` → session; role `user`/unknown/
  unverified → `not_allowed`, no session, alert throttled), `auth-session.test.ts` (no stages;
  role change → null + row deleted + `signin.role_refused`; idle/absolute limits),
  `auth-routes.test.ts` (removed routes 404; sign-out), `admin-actions-guard.test.ts` (every
  admin action refuses role `user`), a new `admin-role.test.ts` (contract table),
  migration test (pre-004 data → post-004 state).
- Update: `jobs.test.ts`, `notify.test.ts`, `payment-confirmation.test.ts`,
  `admin-images-route.test.ts`, `headers.test.ts`, `next-path.test.ts`, `schema.test.ts`,
  `seed.test.ts` as needed.
- Delete: `auth-passkey.test.ts`, `tests/fixtures/webauthn/**`.
- E2E: `fixtures.ts` `signInAsAdmin()` without passkeys; `admin-auth.spec.ts` rewritten (Google
  only, `next`, refusal, rate limit, sign-out, removed pages 404); `admin-access.spec.ts`
  (role `user` refused mid-session); `admin-privacy.spec.ts` (no re-check).
