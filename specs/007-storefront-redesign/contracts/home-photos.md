# Contract: home photos (FR-011, FR-013, FR-014, SC-005)

Decision record: [research.md D3, D4](../research.md#d3-home-photos-where-they-live-and-how-phones-get-small-files-fr-011-fr-013-fr-014-sc-005).

## Files

```text
assets/home-photos/              # originals, committed, not served
├── hero-workshop.jpg            # 2000×848, owner-supplied
├── banner-child-play.jpg        # 2000×848
└── banner-shelf.jpg             # 2000×848
src/lib/home-photos/
├── config.ts                    # hand-written: ids, sources, focal points, crop classes, alt keys
└── manifest.json                # generated by `pnpm photos:home`
public/site-photos/              # generated by `pnpm photos:home`, committed, served at /site-photos/
└── <name>-<variant>.<hash8>.webp
```

`<name>` is the source file name without extension; `<variant>` is `p400`, `p565`, `w800`,
`w1200`, `w1600`, `w2000`; `<hash8>` is the first 8 hex characters of the SHA-256 of the output
bytes.

## Script: `pnpm photos:home`

`scripts/build-home-photos.ts`, run with `tsx` like the other scripts. No arguments.

1. Reads `config.ts`. For each photo, reads `assets/home-photos/<source>`.
2. Phone crops: height = the original's height (848), width = `round(height × 2 / 3)` (565);
   left edge = `clamp(round(focusX × W − width / 2), 0, W − width)`. Writes that crop at 565×848
   and resized to 400×600.
3. Wide: resizes the whole original to 800, 1200, 1600 and 2000 wide (never upscales).
4. Encodes WebP, metadata stripped. Quality: phone and wide set in the script as constants;
   chosen so the hero's `p565` file is ≤ 190 KB.
5. Deletes every file in `public/site-photos/`, writes the new files, writes `manifest.json`
   (sorted keys, so the diff is stable).
6. Prints one line per file (`name  width×height  KB`). Exit 0 on success; exit 1 with a reason
   when a source is missing, smaller than 2000×848 in either dimension, or a budget is exceeded.

Deterministic: same originals and same `sharp` version → same bytes and names.

## Serving

`next.config.ts` `headers()` adds
`{ source: '/site-photos/:path*', headers: [{ key: 'Cache-Control', value: 'public, max-age=31536000, immutable' }] }`.
The static security headers (including `X-Content-Type-Options: nosniff`) already apply to every
path. The proxy matcher already skips paths with a file extension. CSP `img-src 'self'` already
allows them.

## Markup (`src/components/shop/HomePhoto.tsx`, server)

```html
<picture>
  <source media="(min-width: 640px)"
          srcset="/site-photos/…-w800.….webp 800w, …-w1200 1200w, …-w1600 1600w, …-w2000 2000w"
          sizes="100vw">
  <img src="/site-photos/…-p565.….webp"
       srcset="/site-photos/…-p400.….webp 400w, /site-photos/…-p565.….webp 565w"
       sizes="100vw" width="565" height="848" alt="{translated alt}"
       loading="eager|lazy" fetchpriority="high (hero only)" decoding="async"
       class="size-full object-cover {wideObjectPosition}">
</picture>
```

- Hero: `loading="eager"`, `fetchpriority="high"`. Banners: `loading="lazy"`, no priority.
- The box's minimum height comes from the section's CSS (hero phone `min-h-[clamp(560px,150vw,640px)]`,
  from 640 px `min-h-[clamp(460px,48vw,720px)]`; banners phone `min-h-[clamp(520px,140vw,600px)]`,
  from 640 px `min-h-[clamp(420px,42vw,620px)]`; longer text makes the section taller), so
  nothing shifts while the photo loads; the photo is positioned to fill the section from behind,
  and the section background is `bg-ink`, so white text is readable even before the photo
  arrives.
- No `style` attribute.
