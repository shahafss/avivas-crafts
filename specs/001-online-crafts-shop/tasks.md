## Conventions for every task

- Read the referenced contract/data-model section before starting; constraints quoted in a task
  are copied from data-model.md and are not optional.
- Every user-facing string goes into `src/i18n/messages/he.json` **and** `src/i18n/messages/en.json`
  (admin strings: `he.json` and an English placeholder copy in `en.json` to keep key parity).
  Tasks that add strings say which namespace. Because the two message files are shared, UI tasks
  that add strings are **not** marked [P] relative to each other.
- Every admin `page.tsx` (the protected layout's check does not re-run on client-side navigation), Server Action, loader and route handler calls `requireAdmin()` /
  `requireAdminApi()` (T038) first — before parsing any input — and writes `logActivity()` (T030) for changes.
- **Admin GET pages never change state**: rendering an admin page (incl. `/admin/sign-in*` and `/admin/setup`)
  writes nothing, ends no session, logs no activity and sends no email; changes happen only in Server
  Actions and POST handlers. The same-site bounce (contracts/http-endpoints.md) re-sends a cross-site
  top-level GET with the `SameSite=Strict` cookie, so a GET with side effects could be triggered from
  another site; prefetch can trigger it too.
- No raw SQL (`sql.raw` is lint-banned); validate all input with Zod; log only allow-listed fields.
- Run commands with timeouts; never start watch mode or a dev server that does not exit (E2E uses
  Playwright's managed `webServer`). macOS has no GNU `timeout`: use the tool's own timeout setting or
  the test runner's timeout flags.
- Start every shell command with `source ~/.nvm/nvm.sh && nvm use >/dev/null &&` (each shell starts on
  the machine's default Node 22; `nvm use` picks Node 24 from `.nvmrc`, T001).
- The CSP has no `'unsafe-inline'` for styles, so **never use `style="…"` attributes or inline
  style props**: use classes, `<progress>`/`<meter>`, or SVG attributes (`width`, `height`,
  `transform`) for dynamic sizes.
- Next.js 16 specifics: the request interceptor is `src/proxy.ts` (not `middleware.ts`); linting
  runs `eslint` directly. **No data cache is used**: every page renders dynamically (per-request
  CSP nonce) and reads Postgres directly (queries are milliseconds at this scale), so admin changes
  (hide, price) are visible on the very next request; do not use `'use cache'`, `unstable_cache`,
  `revalidateTag` or `updateTag`. `React.cache()` may be used to dedupe queries within one request.
- Cookies: when `APP_ORIGIN` starts with `http://` (local and E2E), public cookies omit `Secure`
  (WebKit rejects Secure cookies over http), the CSP omits `upgrade-insecure-requests`, and HSTS is
  not sent; admin cookies always keep `__Host-` + `Secure` (Chromium accepts them on localhost).
- Server-only modules start with `import 'server-only'`; tests rely on the aliases/mocks from T004;
  CLI scripts run with `tsx --conditions=react-server` so that import resolves to its empty build.
- Product and admin images use a plain `<img>` with a hand-written `srcset`/`sizes`, never
  `next/image` (its markup carries an inline `style` the CSP blocks).
- Database access uses the Drizzle query builder only (incl. `.for('update', { skipLocked: true })`
  and `.returning()`); do not use `db.execute()` — its result shape differs between postgres.js and
  PGlite.
- `tests/e2e/fixtures.ts` belongs to T005 only: E2E test tasks never edit it (that is what keeps them [P]); they use its helpers and its `sql` client and keep spec-specific helpers and queries in the spec file. Every spec file calls `resetDb()` in `test.beforeAll` and creates its own data (T005 isolation rule).
- Tasks whose description says "write the test first" deliver the failing test before the code,
  even when both are in one task.
- **Storefront UI follows `specs/001-online-crafts-shop/design/storefront.md` (binding).** A task's `§` references point into
  that file; read those sections before starting. Use only the `@theme` tokens (T003) — no raw hex
  values in components — and the primitives in `src/components/ui/` (T022) instead of one-off
  markup. Directional icons flip with the `rtl:` variant; prices, order numbers, phones, emails
  and search queries are wrapped in `<bdi>` (§4). Buttons are **never disabled to signal a missing
  choice**: pressing explains what is missing inline and moves focus there (§7.1); the only
  disabled state is `aria-busy` while submitting. Copy speaks as Aviva in the first person
  (Hebrew feminine singular) and addresses customers in the plural (§1 › Voice); never add claims
  that are not true for the shop (no urgency, badges or invented social proof).
- Storefront client islands are only those listed in `specs/001-online-crafts-shop/design/storefront.md` §10; everything else is a
  Server Component. `libphonenumber-js` and `markdown-it` never reach the client bundle.
